# 15 — Qlib 运行资产、备份与恢复验证

**What to build:** 系统所有者可以定期备份 PostgreSQL、不可重建的模型产物和必要配置，并完成一次恢复演练。恢复后既能查询既有研究、预测、回测和模拟账务，也能删除并从 DataSnapshot 重建 QlibDataBundle；备份边界明确区分事实、重要产物和可重建数据包。

**Blocked by:** 07 — Qlib 多因子与 LightGBM 预测选股；14 — 量化研究仪表盘、设置与结果导出

**Status:** ready-for-agent

- [ ] PostgreSQL 定期备份机制覆盖数据快照、研究/模型元数据、预测、目标组合、任务、回测、订单、成交、持仓和绩效结果
- [ ] 已训练且不能仅靠数据库直接使用的模型产物与必要配置进入备份，并以清单和校验值关联对应模型运行
- [ ] QlibDataBundle 目录明确标记为可重建数据包，不作为事实备份要求；其路径与事实/模型产物路径分离
- [ ] 完成一次隔离恢复演练，验证应用可启动并查询代表性的 ResearchExperiment、PredictionRun、BacktestRun 和模拟账户
- [ ] 恢复后的模型产物可加载并对固定输入复现预测；缺失或校验失败时系统返回明确错误，不静默重新训练
- [ ] 删除恢复环境中的 QlibDataBundle 后，可由对应 DataSnapshot、导出器 schema 和 pyqlib 版本确定性重建并通过内容校验
- [ ] 数据导入、结果导出、模型产物、备份和恢复路径均限制在各自配置目录内
- [ ] 备份保留、恢复步骤、依赖/Qlib 版本升级和镜像更新流程有可执行文档及最近一次演练记录
