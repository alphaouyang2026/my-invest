# 个人日本股票研究与模拟交易系统 Spec

> 文档状态：Draft for Review  
> 版本：0.4
> 日期：2026-08-26
> 目标市场：日本股票（东京证券交易所 Prime Market 普通股）  
> 使用方式：个人单用户，个人电脑本机部署  
> 系统范围：研究、历史回测和模拟交易；不提供实时行情与实盘交易

---

## 1. 文档目的

本文定义一套供个人使用、可解释、可复现、由 Qlib 驱动的日本股票量化研究与模拟交易系统。系统以历史数据为基础，支持：

1. 市场与证券数据管理；
2. 多因子研究、机器学习预测、股票筛选与信号生成；
3. 基于规则或模型预测的投资组合构建、目标权重建议与风险约束；
4. 一次性历史回测和隐藏未来数据的交互式历史重放；
5. 虚拟账户、持仓、净值和绩效分析；
6. 策略、参数、数据版本及结果追踪。

系统仅用于投资研究和历史模拟，不连接券商、不发送真实订单，也不保证投资收益。

## 2. 产品目标与边界

### 2.1 目标

- 使用统一的历史数据完成研究、信号、回测和模拟交易；
- 以 Qlib 为核心研究引擎，复用其特征、数据集、模型、选股、组合、回测和实验管理能力；
- 支持从动量基线扩展到多因子、机器学习预测和组合优化，而不重复建设通用量化研究框架；
- 防止未来函数、幸存者偏差和数据泄漏；
- 支持东京证券交易所 Prime Market 普通股及其历史交易规则；
- 对策略结果提供收益、风险、交易成本和归因分析；
- 通过简单的三层架构降低个人部署及维护成本；
- 保证每次回测都能追溯到策略、参数、代码和数据版本。

### 2.2 非目标

本系统不包含：

- 实时或延迟实时行情订阅；
- 券商 API、账户同步和券商对账；
- 真实下单、撤单及成交回报；
- 自动或半自动实盘交易；
- OMS/EMS、实盘盘中风控和 Kill Switch；
- 高频、超低延迟、日内策略和分钟/Tick 数据；
- 融资融券、期权、期货和其他衍生品交易；
- 多用户、机构权限体系和监管报送。

### 2.3 成功标准

- 相同的数据快照、策略版本、参数和随机种子产生一致结果；
- 回测只读取当时已知的数据；
- 模拟成交遵守对应市场的历史交易规则；
- 显式成本与滑点分开计算并可配置；
- 回测结果能够解释到信号、模拟订单、成交和持仓变化；
- 免费数据阶段明确展示约两年历史、12 周延迟、潜在幸存者偏差和现金股息缺失等限制；
- 常用页面和任务适合个人电脑运行。
- 至少一个 Qlib 模型能够完成训练、预测、选股、目标组合、研究回测和本地精确重放闭环。

## 3. 用户与访问控制

系统仅面向一个所有者。用户可以管理数据、策略、回测任务和模拟账户。

第一版仅限本机访问，不建设登录和角色权限系统。J-Quants API key 通过环境变量或本地密钥文件配置，不写入源码、数据库日志或导出结果。

## 4. 核心业务流程

### 4.1 数据准备流程

```text
导入历史数据
→ 格式与完整性校验
→ 证券标识和交易日历标准化
→ 保存原始数据及数据版本
→ 计算复权数据与研究特征
→ 标记可用于回测的数据快照
```

### 4.2 研究流程

```text
选择市场与股票池
→ 选择研究日期和数据快照
→ 选择 Qlib 特征集、标签、数据切分与模型
→ 计算因子并训练或加载模型
→ 生成预测、选股结果与目标组合
→ 检查覆盖率、分布、IC、分组表现和样本外表现
→ 保存数据、特征、模型、策略、参数与实验版本
```

### 4.3 回测与模拟交易流程

```text
选择策略、股票池和历史区间
→ 按历史时间顺序读取当时可见的数据
→ 生成信号与目标持仓
→ 执行模拟风险检查
→ 生成模拟订单
→ 按成交模型计算模拟成交
→ 更新虚拟现金、持仓和净值
→ 输出收益、风险、成本和归因结果
```

回测和模拟交易共享同一套信号、组合、风险及成交模块。区别仅在于运行方式：

- **自动回测**：一次性处理完整历史区间；
- **历史重放**：后端固定 `as_of`，用户每周选择股票并填写目标权重，然后推进到下一决策日；默认决策日为该周最后一个实际交易日，所有数据查询均不得返回 `as_of` 之后的信息。

历史重放允许修改过去的决定，但修改必须创建新的重放分支，不能覆盖已经看过后续结果的原始决定。重放结束后比较用户、策略和内部基准的收益、回撤、换手、成本、每期持仓差异及信号一致程度。

## 5. 总体架构

系统采用前端、后端、数据库三层架构。Qlib 作为后端内的核心研究运行时，不拆分为独立微服务。所有业务能力均作为后端内部模块运行。

```text
┌──────────────────────────────────────────────────────┐
│ 前端 Web                                             │
│ 仪表盘 / 数据 / 选股 / 策略 / 回测 / 历史重放 / 分析 │
└─────────────────────────┬────────────────────────────┘
                          │ HTTP / REST
┌─────────────────────────▼────────────────────────────┐
│ 后端应用                                              │
│ 数据与快照 │ Qlib 研究/模型/选股 │ 组合与风险       │
│ 回测与模拟成交 │ 历史重放 │ 绩效分析 │ 任务与结果导出 │
└─────────────────────────┬────────────────────────────┘
                          │ SQL
┌─────────────────────────▼────────────────────────────┐
│ PostgreSQL                                           │
│ 历史数据 / 特征 / 策略 / 任务 / 模拟交易 / 分析结果 │
└──────────────────────────────────────────────────────┘
```

### 5.1 前端

前端负责交互和可视化，不承载策略计算：

- 查看数据状态和市场概览；
- 配置股票池、策略、参数与回测区间；
- 发起、取消和查看回测任务；
- 查看信号、模拟订单、持仓、净值和绩效；
- 比较不同策略版本和回测结果；
- 导出 CSV 或报告。

### 5.2 后端模块

1. **数据管理模块**：导入、校验和查询标的主数据、历史日线、调整因子、财务摘要及决算发表日历；维护点时事实和 `DataSnapshot`。
2. **Qlib 研究引擎模块**：通过稳定 interface 封装 Qlib 的特征表达、Dataset/DataHandler、模型训练与推理、信号分析、选股、研究型组合和实验记录。
3. **Qlib 数据适配模块**：把不可变 `DataSnapshot` 确定性转换为 Qlib 原生 file provider 可读的日历、instruments、行情和质量字段；产物是可删除、可重建的不可变 `QlibDataBundle`，不包含实验标签或动态研究股票池。
4. **策略与模型模块**：保存特征集、标签、模型、选股/组合策略、参数、股票池和版本信息。
5. **组合构建模块**：优先消费 Qlib 的预测和策略结果生成目标权重，并补充日本市场、现金、换手和集中度约束。
6. **风险模块**：执行模拟交易前检查，并计算组合风险指标。
7. **回测模块**：协调 Qlib 研究型回测和本地精确执行重放；前者用于快速研究，后者形成可审计账务结果。
8. **模拟成交模块**：根据历史价格、日本市场规则、费用和滑点生成模拟成交结果。
9. **历史重放模块**：强制历史时点隔离，调用 Qlib 生成预测/目标组合，并保存用户决策和不可覆盖的分支历史。
10. **模拟账户模块**：以定点数维护虚拟现金、待结算现金、持仓、成本、净值和损益。
11. **绩效分析模块**：优先复用 Qlib 的组合分析，并以日本交易日历和本地账务结果校正收益、回撤、波动率、风险调整收益、换手、成本和归因。
12. **任务模块**：管理数据导入、QlibDataBundle 构建、模型训练、推理、回测和精确重放等后台任务。

模块通过后端内部接口协作。对外只暴露少量面向用例的接口，例如“创建回测”“推进模拟日期”“查询组合快照”，避免前端依赖内部计算步骤。

Qlib 与本地模块的职责、适配 seam 和分阶段落地方案见 [Qlib 核心采用方案](./design/qlib-evaluation.md)，数据适配边界见 [ADR-0001](./adr/0001-use-qlib-data-bundles.md)。

### 5.3 PostgreSQL

PostgreSQL 是唯一的持久化基础设施，用于保存：

- 证券、市场规则和交易日历；
- 历史日线、调整因子、财务摘要和决算发表日历；
- 特征定义、预测、信号和数据版本；
- 模型、策略、参数、股票池、实验和代码版本；
- 回测任务、运行日志和结果；
- 模拟账户、订单、成交、持仓及净值；
- 风险指标和绩效分析结果。

第一版不引入 Redis、Kafka、独立对象存储或分布式任务系统。后台任务由 PostgreSQL 任务表和单个工作进程串行执行；其他任务排队。取消任务时保留运行定义和进度，清理不完整明细，取消结果不得参与策略比较。

QlibDataBundle 由 `DataSnapshot` 确定性生成，是可重建的数据包而非事实源；标签和动态 `ResearchUniverse` 由 `ResearchExperiment` 定义并在 `ResearchRun` 中实例化。模型中间产物同样不改变 PostgreSQL 的事实源地位。引入 Qlib Python 依赖不代表部署 Redis 或 MongoDB 服务；未使用的可选集成不得成为运行前提。

## 6. 数据规格

### 6.1 数据类别

| 类别 | 最低粒度 | 主要字段 | 用途 |
|---|---:|---|---|
| 上市标的主数据 | 快照 | 代码、名称、市场、行业、证券类别 | Prime 普通股股票池 |
| 日线行情 | 日 | OHLCV、成交额、调整价格、调整因子 | 研究、信号、回测 |
| 来源市场日历 | 日 | 日期、休市/交易日分类 | 同步范围发现；经校验后形成正式交易日历 |
| 财务摘要 | 披露事件 | 披露时间、主要业绩与预测字段、版本 | 第二阶段基本面因子 |
| 决算发表日历 | 事件 | 计划发表日期、证券代码 | 事件提示与研究 |
| 模拟交易数据 | 模拟事件 | 订单、成交、持仓、现金、费用 | 组合和绩效分析 |

第一版数据源为 J-Quants API V2 Free。根据截至 2026-08-15 的官方资料复核，免费版约有滚动两年历史、延迟 12 周、限制 5 calls/min 且不支持 CSV 批量下载；免费端点包括上市标的主数据、股票全日日线、市场日历、财务摘要和决算发表日历。TOPIX、完整财务报表、现金股息明细及分钟/Tick 数据不属于 Free。

详细权限、来源和变化风险见 [J-Quants API 免费版可用数据调查](research/jquants-free-plan-data.md)。套餐可能变化，每次升级或重新实施数据适配器前必须复核官方资料。

第一版只使用全日日线。财务摘要完成接入和点时版本验证之前，策略仅使用价格、成交量与流动性因子。

### 6.2 点时一致性

研究数据至少保存：

- `event_time`：经济事件实际发生时间；
- `publish_time`：信息公开时间；
- `ingested_at`：系统导入时间；
- `effective_from/effective_to`：数据版本有效区间；
- `source` 和 `source_version`：来源及版本。

回测只能读取模拟时点已经公开且已生效的数据。财务数据不得按报告期末日期提前使用。同步程序必须记录每个端点实际返回的最早和最晚日期，不能硬编码“两年”的精确边界。

### 6.3 数据质量

导入时至少检查：

- 主键重复、字段缺失和时间倒序；
- 价格为负、成交量异常和 OHLC 逻辑错误；
- 停牌、零成交和交易日历一致性；
- 公司行动与复权因子的异常跳变；
- 财务数据发布日期、报告期和修订版本；
- 数据覆盖率、延迟和异常值。

严重错误的数据批次不得用于回测，并应保留错误原因。关键价格缺失时证券不可交易；非关键研究字段缺失时可以排除证券并告警；若缺失影响已持有证券估值或组合账务，整个任务失败，不得静默产生结果。

### 6.4 同步、修订与快照

- 用户触发幂等的 `sync now`：首次抓取账户实际可见的完整历史，后续重取最近 30 个自然日，距离上次完整核对超过 30 天时自动执行完整核对；暂不提供定时调度或用户自选日期范围；
- J-Quants 全市场日线按 `date` 请求。同步器先无参数读取来源市场日历以发现账户实际可见日期，再逐交易日抓取日线并遍历 `pagination_key`；不得依赖未文档化的超范围请求裁剪，也不得硬编码“两年”的精确边界；
- 所有请求共享 5 calls/min 限流器，处理 `Retry-After`、带随机抖动的指数退避和 HTTP 429/可重试故障；首次或完整核对是允许持续数小时的后台任务；
- 日线端点返回的证券事实在同步层全部保存，不按当前 Prime 名单或当前证券类别过滤；历史时点 Prime 普通股资格由股票池模块依据主数据快照判断；
- 回测只读 PostgreSQL，不在运行期间调用外部数据源；
- 数据先写入不可见的 endpoint publication generation，完整分页并通过结构校验后以短事务发布；失败或取消的 generation 不改变此前正式数据；
- 规范化记录以业务键和内容哈希区分新增、未变和上游修订；修订生成不可变新版本，旧值不物理覆盖；
- 已完成回测绑定不可变的数据快照，不随数据修订自动改变；
- 每次同步以日线实际 `coverage_end` 请求并保存对应日期的标的快照，为未来积累可靠的历史股票池；不使用今天的主数据冒充历史状态，也不虚构首次同步之前的历史成员关系；
- 免费历史无法证明包含完整退市证券，旧区间回测必须显示潜在幸存者偏差警告；
- 脱敏原始响应、失败 generation 和临时 staging 默认保留 90 天；规范化版本、标的快照、运行/publication 元数据、覆盖范围和内容哈希永久保留。

## 7. 日本市场与股票池规则

### 7.1 市场范围

第一版仅包含东京证券交易所 Prime Market 普通股，排除 ETF、ETN、REIT、优先股及其他非普通股证券。基础币种为 JPY，只支持现金股票多头策略。

股票池在每个历史时点按当时保存的标的快照构建，并应用以下过滤：

- 最近约 20 个交易日平均成交额不少于 5 亿日元，阈值可配置；
- 有足够历史数据完成约 126 个交易日动量计算和约 21 个交易日跳过期；
- 决策日具有有效价格、成交量和证券状态；
- 免费数据无法确认完整退市历史时，显示幸存者偏差警告。

### 7.2 市场规则配置

日本市场规则通过配置管理：

- 交易日历和交易时段；
- 结算周期；
- 最小交易单位和价格精度；
- 涨跌停、停牌及不可交易状态；
- 手续费、税费和其他成本；
- 公司行动处理规则；
- 现金结算和可用资金规则。

所有规则仅用于历史模拟，不用于校验或发送真实订单。

当前 J-Quants V2 Free 提供市场日历端点。数据同步模块只把它作为来源可见日期发现机制，用于逐日规划行情请求；来源权限窗口不直接等同于系统认可的市场规则。数据质量模块将来源日历规范化、与行情交叉校验并通过可替换的 TradingCalendar interface 提供 `is_open`、前一/下一交易日和交易日窗口等业务能力。未经校验的来源日期不得直接供股票池或回测使用。

## 8. 研究、信号与策略

### 8.1 因子研究

首个黄金研究基线为价格动量。第一步验证 QlibDataBundle、表达式、标签、因子评价和 `RankedScores` 链路；后续 ticket 再把同一分数接入组合与精确重放，不限制后续研究范围：

- 使用约 6 个月（126 个交易日）收益；
- 跳过最近约 1 个月（21 个交易日）；
- 每周按动量分数排序；
- 选择排名最高的 20 只股票；
- 采用等权目标，不使用排名缓冲或最低持有期；
- 周五收盘后决策；周五休市时使用该周最后一个交易日；
- 下一实际交易日开盘模拟成交；
- 窗口、持仓数和流动性阈值均可配置，但上述值是黄金测试基线。

Phase 1 先以 6-1 动量完成因子研究，不生成 `TargetPortfolio` 或运行 `ResearchBacktest`。随后引入价格量特征、Qlib Alpha158/Alpha360 中可由现有数据可靠计算的因子，并建立 LightGBM 等预测基线。价值、质量、成长等基本面因子在财务摘要点时语义验证完成后进入后续阶段。

研究结果应展示覆盖率、缺失率、分布、相关性、IC/Rank IC、分组收益、样本外表现、换手和成本敏感性。时间序列训练、验证和测试必须按时间切分，不得随机打散造成信息泄漏。

### 8.2 信号输出

信号至少包含：

- 证券和模拟日期；
- 策略及模型版本；
- 原始分数和标准化分数；
- 方向、置信度和原因码；
- 使用的数据快照；
- 失效条件或有效期。

### 8.3 策略版本

每次运行必须固定并记录：

- 策略定义和参数；
- 股票池及基准；
- 数据快照；
- 代码版本或构建标识；
- 费用、滑点和成交模型；
- 随机种子（如适用）。

策略和模型通过受控的 Qlib 适配 interface 注册，声明特征集、标签、数据切分、模型、选股/组合策略及参数。数据库保存定义引用、参数、版本和产物元数据，禁止保存并执行任意 Python 代码。界面只提供已声明参数的配置能力。

参数试验按研究系列归组，必须展示试验次数、样本外结果和成本敏感性，降低挑选最佳结果造成的数据窥探偏差。

## 9. 组合与模拟风险

### 9.1 组合构建

支持：

- 等权、评分加权和优化权重；
- 单股、行业和市场权重上限；
- 最低现金比例；
- 换手限制；
- 最小持仓和最小调仓金额；
- JPY 现金和持仓估值。

Qlib 的预测分数和策略用于生成候选目标组合；本地组合模块负责施加日本市场与可执行性约束。Qlib 的 `TopkDropoutStrategy` 等策略可以用于实验，但其换股数、缓冲和最低持有期等语义必须显式记录，不能冒充不含这些规则的动量黄金基线。

首个策略的默认组合规则为：持有 20 只、等权、保留至少 5% 现金、单股目标权重不超过 5%。整手取整和费用导致无法精确达到目标时，剩余资金保留为现金。

### 9.2 模拟交易前检查

模拟订单生成前检查：

- 可用虚拟现金；
- 最大持仓和集中度；
- 股票是否处于可交易状态；
- 交易单位和价格精度；
- 成交量参与率；
- 预估费用、滑点和换汇需求；
- 调仓后组合约束。

风险检查失败时不生成模拟成交，并记录原因。

研究模式使用归一化净值；可执行性模式默认初始资金为 500 万日元，并同时提供 100 万、500 万和 1000 万日元的容量对比。可执行性模式模拟日本股票交易单位、现金余额及无法买入的目标仓位。

## 10. 回测与模拟成交

### 10.1 回测原则

- 使用点时一致的数据；
- 信号时间、下单时间和成交时间严格分离；
- 不允许使用当时尚未公开的数据；
- 不允许在没有成交量或不可交易状态下成交；
- 公司行动、退市和股票池历史变化必须被处理；
- 显式费用、滑点和现金结算假设必须写入结果。

### 10.2 成交模型

模拟成交支持配置：

- 默认使用下一交易日开盘价；
- 固定百分比滑点，默认单边 10 个基点且可配置；
- 成交量参与率上限；
- 手续费、税费和最低费用；
- 停牌、涨跌停及无成交量限制；
- 部分成交和未成交订单过期；
- 市场最小交易单位。

默认规则不得假设信号能够以生成信号时已经结束的同一根 K 线价格成交。

显式成本与滑点必须分开计算。系统提供：

- **零成本场景**：只用于观察信号理论表现；
- **基准成本场景**：用户配置佣金、最低费用和其他显式费用；
- **压力成本场景**：默认使用基准显式费用的两倍；
- **自定义场景**：允许覆盖显式费用和滑点参数。

预设不绑定或宣称代表任何券商的真实收费。结果同时展示毛收益、显式成本、滑点损失和净收益。

现金规则支持两种模式：默认模式允许卖出成交所得在同日调仓中使用；严格结算模式维护待结算现金，在结算完成前不可用于买入。

调整价格用于研究收益连续性。免费版没有完整公司行动及现金股息明细，因此不得从价格跳变臆测事件；可执行性回测只处理能够可靠识别的调整，并明确提示现金股息收益可能被低估。

### 10.3 模拟交易状态

模拟订单采用简化状态：

```text
CREATED → FILLED
        → PARTIALLY_FILLED
        → REJECTED
        → EXPIRED
```

状态由回测引擎和成交模型产生，不代表真实券商订单。

### 10.4 结果指标

至少计算：

- 累计收益和年化收益；
- 相对基准收益；
- 年化波动率；
- 最大回撤；
- Sharpe、Sortino 和 Calmar；
- 胜率和盈亏比；
- 换手率、交易次数和持有期；
- 显式费用、滑点及现金占用影响；
- 行业、市场和个股贡献。

内部基准为“当时可投资股票池的月度等权组合”，不是 TOPIX。结果同时展示基准毛收益和使用相同成本模型后的净收益，策略主要与净基准比较。

策略状态只允许：

- `EXPERIMENTAL`：逻辑、数据和黄金测试通过；
- `PROMISING`：样本外、成本和参数稳定性检查通过；
- `INSUFFICIENT_DATA`：观察期不足。

J-Quants Free 阶段禁止标记为 `VALIDATED`。约两年历史在扣除动量预热期后不能支持强统计结论，不能为了延长评估期临时缩短策略窗口。

## 13. 前端工作台

首期页面：

1. **仪表盘**：数据状态、近期回测、模拟组合和关键指标；
2. **数据中心**：数据覆盖、缺失、异常和导入任务；
3. **股票研究**：行情、财务、因子、事件和信号；
4. **策略中心**：策略参数、版本和股票池；
5. **回测中心**：创建任务、查看进度及比较结果；
6. **历史重放**：每周隐藏未来数据进行选股和目标权重决策；
7. **模拟账户**：虚拟现金、订单、成交、持仓和净值；
8. **绩效分析**：策略、用户和内部基准的收益、风险、回撤、成本及持仓差异；
9. **设置**：市场规则、费用模型、数据源和本地密钥说明。

所有结果必须明确标识为“历史回测”或“模拟交易”，不得表现为真实账户或真实成交。

## 14. 非功能要求

### 14.1 可复现性

- 相同输入产生相同输出；
- 每次运行保存数据、策略、参数和代码版本；
- 任务失败后可以从头安全重跑；
- 关键计算采用固定精度和明确舍入规则。

### 14.2 性能

- 常用页面查询 P95 小于 2 秒；
- 后台回测不得阻塞普通查询；
- 回测进度和预计处理范围可见；
- 第一版存储容量覆盖 J-Quants Free 股票日线端点实际可见的约两年全部返回记录；投资与回测股票池仍默认限定为 Prime 普通股。

### 14.3 安全与备份

- Docker Compose 中前端和后端默认仅绑定 `localhost`，第一版不提供远程访问和登录；
- 密钥不得写入源码和日志；
- PostgreSQL 定期备份并进行恢复验证；
- 数据导入文件和回测导出文件限制在配置目录内；
- 依赖和镜像定期更新。

### 14.4 可维护性

- 前端、后端和数据库是仅有的部署单元；
- 后端模块接口清晰，避免业务逻辑散落在路由和 SQL 中；
- 数据库变更使用迁移脚本；
- 市场规则、费用和滑点通过配置或数据库管理；
- 日志包含任务 ID 和回测运行 ID，便于定位问题。

## 15. 推荐技术基线

- 前端：React / Next.js + TypeScript；
- 后端：Python + FastAPI；
- 后端运行时：Python 3.12，Docker 基础镜像 `python:3.12-slim`；
- 量化研究引擎：Microsoft Qlib，当前基线通过 PyPI 安装 `pyqlib==0.9.7` 并锁定完整依赖；本地检出只用于源码参考；
- 数据处理：Qlib + Pandas/NumPy；非 Qlib 数据管道可使用 Polars；
- 模型与优化：优先使用 Qlib 集成的模型与 portfolio 能力；需要组合优化时使用其 CVXPY 依赖；
- 数据库：PostgreSQL；
- 数据库访问：SQLAlchemy 或同类方案；
- 后台任务：单个后端工作进程 + PostgreSQL 任务表；
- 测试：Pytest、前端单元测试及端到端测试；
- 部署：个人电脑上的 Docker Compose，包含前端、后端和 PostgreSQL，仅监听本机。

第一版不使用微服务、Redis、Kafka、Kubernetes、独立对象存储和券商 SDK。

## 16. 测试与验收

### 16.1 测试层级

- 单元测试：因子、费用、复权、组合、现金和风险计算；
- 属性测试：账务恒等式、状态转换和数值边界；
- 集成测试：后端与 PostgreSQL、数据导入和任务运行；
- 黄金数据测试：固定数据快照对应固定信号及回测结果；
- Qlib 适配测试：QlibDataBundle 导出确定性、日历/标识/字段一致性、表达式结果、时间切分和数据包可重建性；
- 双层回测测试：Qlib 研究回测与本地定点数重放的持仓、换手、成本和收益差异在容差内，超差必须生成可解释报告；
- 回放测试：完整历史区间的模拟交易；
- 时间隔离测试：历史重放的所有查询都无法读取 `as_of` 之后的数据；
- 数据适配测试：J-Quants 日历范围发现、逐日行情、分页、限流、429/`Retry-After` 重试、schema 变化、空响应、修订、generation 原子可见性和覆盖范围；普通 CI 使用脱敏 fixtures，不调用真实 J-Quants；
- 端到端测试：前端创建回测并查看结果。

### 16.2 验收条件

- 系统能够通过 J-Quants V2 Free 发现账户可见日期并导入主数据和全市场历史日线，随后在股票池层筛选历史时点 Prime 普通股；真实 Free key 的 calendar、master 和单日 bars smoke sync 是数据源验收条件；
- 能运行 6 个月动量、跳过 1 个月、20 只等权的黄金基准策略；
- 至少一个 Qlib 模型能够完成训练、预测、选股、目标组合和研究回测，并由本地执行模块完成精确重放；
- 能按周进行隐藏未来数据的历史重放，并创建不可覆盖的决策分支；
- 模拟订单、成交、持仓、现金和净值保持一致；
- 交易单位、不可交易状态、显式费用、固定滑点和现金模式按配置生效；
- 回测结果可追溯到策略版本和数据快照；
- 系统没有连接券商或发送真实订单的能力；
- 前端、后端和 PostgreSQL 可以通过单套部署配置启动。

## 17. 分阶段路线图

### Phase 0：基础架构

- 建立前端、后端和 PostgreSQL 三层项目；
- 完成数据库迁移、配置、日志和任务框架。

### Phase 1：数据与研究

- 接入 J-Quants V2 Free 的来源日历、主数据和历史日线，实测各端点覆盖范围并建立稳定证券身份；

### Phase 2：回测

- 引入 Qlib Alpha 特征和至少一个机器学习预测/选股基线；

- 实现虚拟账户、持仓、现金和净值；
- 提供 Qlib 研究回测、本地精确重放和绩效差异分析页面。

### Phase 3：历史重放与基本面扩展

- 支持按周推进的历史重放、用户目标权重和决策分支；
- 支持策略版本和回测结果比较；
- 验证财务摘要的披露时间及修订语义后加入基本面因子；
- 增加组合优化、风险暴露分析、走步训练和模型滚动比较；
- 增加报告导出、性能优化和备份恢复。

免费数据完成端到端验证且至少一个策略达到 `PROMISING` 后，重新核对当前套餐并考虑升级 J-Quants Light，以取得更长历史和官方基准。后续扩展仍以历史研究和模拟交易为范围，不规划实盘交易接入。

## 18. 主要风险

| 风险 | 后果 | 缓解措施 |
|---|---|---|
| 数据偏差或未来函数 | 回测结果虚高 | 点时数据、历史成分、发布日期和黄金测试 |
| 过拟合 | 样本外失效 | 滚动验证、样本外测试、参数稳定性分析 |
| 流动性高估 | 模拟结果不现实 | 成交量参与率、滑点和容量压力测试 |
| 市场规则错误 | 成交与持仓失真 | 市场规则配置、固定案例和回放测试 |
| 免费版缺少完整公司行动和股息 | 收益被低估或账务不完整 | 使用调整价格、明确局限、只处理可靠事件 |
| 免费版历史过短 | 统计结论不可靠 | 禁止 VALIDATED 状态、显示观察点、满足条件后升级 Light |
| 幸存者偏差 | 策略收益虚高 | 显示警告、持续保存标的快照、升级后重新验证 |
| 本地数据损坏 | 历史结果丢失 | 定期备份和恢复演练 |
| 资源不足 | 回测过慢或失败 | 后台任务、查询索引、分批计算和容量限制 |

## 19. 已确认产品决策

1. 第一版投资与回测股票池为东京证券交易所 Prime Market 普通股；同步层保留 J-Quants 股票日线端点返回的全部证券事实，不用当前名单过滤历史行情；
2. 数据源为 J-Quants API V2 Free，只使用日线，免费阶段定位为原型；
3. 核心用途是量化策略验证、个人选股和目标权重建议；
4. Qlib 是特征、模型、选股、组合、研究回测和实验管理的核心引擎；PostgreSQL 点时事实源与本地定点数账务是其可信护栏；
5. 同时支持一次性回测和按周交互的历史重放；
6. 首个黄金策略为 6 个月动量、跳过 1 个月、20 只等权，但它不是系统能力上限；
7. 内部基准为当时可投资股票池的月度等权组合，不冒充 TOPIX；
8. 默认初始资金 500 万日元，并比较 100 万和 1000 万日元；
9. 提供零成本、基准成本和压力成本，滑点默认单边 10 个基点；
10. 策略和模型通过受控 Qlib 适配 interface 注册，界面只配置已声明参数；
11. 单机 Docker Compose 部署，前端、后端和 PostgreSQL 仅监听本机；
12. 免费数据端到端验证完成且至少一个策略达到 `PROMISING` 后考虑升级 Light；
13. 系统不会连接券商，也不规划实盘交易。

## 附录 A：术语

- **点时一致性（Point-in-time）**：只使用历史时点当时已经公开的信息；
- **回测**：在一段历史区间内自动运行策略和模拟成交；
- **模拟交易**：基于历史数据产生虚拟订单、成交、持仓和净值；
- **数据快照**：一次运行所使用的数据范围和版本标识；
- **QlibDataBundle（Qlib 数据包）**：从单一 DataSnapshot 确定性构建、供 Qlib 原生 provider 读取、可删除重建的不可变市场数据包，不含实验标签和动态研究股票池；
- **ResearchExperiment（研究实验）**：不可变的研究语义定义；相同规范通过指纹复用，定义变化即创建新实验；
- **ResearchRun（研究运行）**：某个研究实验的一次实际执行，记录运行环境、进度、警告和产物；
- **RankedScores（排名分数）**：因子研究和模型预测共享的逐证券分数、平均秩、百分位及排除原因 interface；
- **滑点**：模拟成交价相对参考价格的不利偏移；
- **最大回撤**：净值从历史高点到之后低点的最大跌幅。
