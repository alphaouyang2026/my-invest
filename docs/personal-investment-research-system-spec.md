# 个人日本股票研究与模拟交易系统 Spec

> 文档状态：Draft for Review  
> 版本：0.3  
> 日期：2026-08-11  
> 目标市场：日本股票（东京证券交易所 Prime Market 普通股）  
> 使用方式：个人单用户，个人电脑本机部署  
> 系统范围：研究、历史回测和模拟交易；不提供实时行情与实盘交易

---

## 1. 文档目的

本文定义一套供个人使用、可解释、可复现的日本股票研究与模拟交易系统。系统以历史数据为基础，支持：

1. 市场与证券数据管理；
2. 因子研究、股票筛选与信号生成；
3. 投资组合构建、目标权重建议与风险约束；
4. 一次性历史回测和隐藏未来数据的交互式历史重放；
5. 虚拟账户、持仓、净值和绩效分析；
6. 策略、参数、数据版本及结果追踪。

系统仅用于投资研究和历史模拟，不连接券商、不发送真实订单，也不保证投资收益。

## 2. 产品目标与边界

### 2.1 目标

- 使用统一的历史数据完成研究、信号、回测和模拟交易；
- 防止未来函数、幸存者偏差和数据泄漏；
- 支持东京证券交易所 Prime Market 普通股及其历史交易规则；
- 对策略结果提供收益、风险、交易成本和归因分析；
- 通过简单的三层架构降低个人部署及维护成本；
- 保证每次回测都能追溯到策略、参数、代码和数据版本。

### 2.2 非目标

本系统不包含：

- 实时或延迟实时行情订阅；
- 券商 API、账户同步和券商对账；
- 真实下单、撤单及成交回报；
- 自动或半自动实盘交易；
- OMS/EMS、实盘盘中风控和 Kill Switch；
- 高频、超低延迟、日内策略和分钟/Tick 数据；
- 融资融券、期权、期货和其他衍生品交易；
- 多用户、机构权限体系和监管报送。

### 2.3 成功标准

- 相同的数据快照、策略版本、参数和随机种子产生一致结果；
- 回测只读取当时已知的数据；
- 模拟成交遵守对应市场的历史交易规则；
- 显式成本与滑点分开计算并可配置；
- 回测结果能够解释到信号、模拟订单、成交和持仓变化；
- 免费数据阶段明确展示约两年历史、12 周延迟、潜在幸存者偏差和现金股息缺失等限制；
- 常用页面和任务适合个人电脑运行。

## 3. 用户与访问控制

系统仅面向一个所有者。用户可以管理数据、策略、回测任务和模拟账户。

第一版仅限本机访问，不建设登录和角色权限系统。J-Quants API key 通过环境变量或本地密钥文件配置，不写入源码、数据库日志或导出结果。

## 4. 核心业务流程

### 4.1 数据准备流程

```text
导入历史数据
→ 格式与完整性校验
→ 证券标识和交易日历标准化
→ 保存原始数据及数据版本
→ 计算复权数据与研究特征
→ 标记可用于回测的数据快照
```

### 4.2 研究流程

```text
选择市场与股票池
→ 选择研究日期和数据快照
→ 计算因子与信号
→ 检查覆盖率、分布和缺失值
→ 查看收益相关性与分组表现
→ 保存策略及参数版本
```

### 4.3 回测与模拟交易流程

```text
选择策略、股票池和历史区间
→ 按历史时间顺序读取当时可见的数据
→ 生成信号与目标持仓
→ 执行模拟风险检查
→ 生成模拟订单
→ 按成交模型计算模拟成交
→ 更新虚拟现金、持仓和净值
→ 输出收益、风险、成本和归因结果
```

回测和模拟交易共享同一套信号、组合、风险及成交模块。区别仅在于运行方式：

- **自动回测**：一次性处理完整历史区间；
- **历史重放**：后端固定 `as_of`，用户每周选择股票并填写目标权重，然后推进到下一决策日；默认决策日为该周最后一个实际交易日，所有数据查询均不得返回 `as_of` 之后的信息。

历史重放允许修改过去的决定，但修改必须创建新的重放分支，不能覆盖已经看过后续结果的原始决定。重放结束后比较用户、策略和内部基准的收益、回撤、换手、成本、每期持仓差异及信号一致程度。

## 5. 总体架构

系统采用前端、后端、数据库三层架构。所有业务能力均作为后端内部模块运行，不拆分微服务。

```text
┌──────────────────────────────────────────────────────┐
│ 前端 Web                                             │
│ 仪表盘 / 数据 / 选股 / 策略 / 回测 / 历史重放 / 分析 │
└─────────────────────────┬────────────────────────────┘
                          │ HTTP / REST
┌─────────────────────────▼────────────────────────────┐
│ 后端应用                                              │
│ 数据管理 │ 研究与信号 │ 组合与风险 │ 回测与模拟成交  │
│ 历史重放 │ 绩效分析   │ 任务调度   │ 结果导出        │
└─────────────────────────┬────────────────────────────┘
                          │ SQL
┌─────────────────────────▼────────────────────────────┐
│ PostgreSQL                                           │
│ 历史数据 / 特征 / 策略 / 任务 / 模拟交易 / 分析结果 │
└──────────────────────────────────────────────────────┘
```

### 5.1 前端

前端负责交互和可视化，不承载策略计算：

- 查看数据状态和市场概览；
- 配置股票池、策略、参数与回测区间；
- 发起、取消和查看回测任务；
- 查看信号、模拟订单、持仓、净值和绩效；
- 比较不同策略版本和回测结果；
- 导出 CSV 或报告。

### 5.2 后端模块

1. **数据管理模块**：导入、校验和查询标的主数据、历史日线、调整因子、财务摘要及决算发表日历。
2. **研究与信号模块**：因子计算、股票筛选、信号生成及研究统计。
3. **策略模块**：保存策略定义、参数、股票池和版本信息。
4. **组合构建模块**：生成目标权重，处理仓位、换手、现金和集中度约束。
5. **风险模块**：执行模拟交易前检查，并计算组合风险指标。
6. **回测模块**：按历史事件顺序驱动策略、组合和模拟成交。
7. **模拟成交模块**：根据历史价格、市场规则、费用和滑点生成模拟成交结果。
8. **历史重放模块**：强制历史时点隔离，保存用户决策和不可覆盖的分支历史。
9. **模拟账户模块**：维护虚拟现金、待结算现金、持仓、成本、净值和损益。
10. **绩效分析模块**：计算收益、回撤、波动率、风险调整收益、换手和归因。
11. **任务模块**：管理数据导入、特征计算和回测等后台任务。

模块通过后端内部接口协作。对外只暴露少量面向用例的接口，例如“创建回测”“推进模拟日期”“查询组合快照”，避免前端依赖内部计算步骤。

### 5.3 PostgreSQL

PostgreSQL 是唯一的持久化基础设施，用于保存：

- 证券、市场规则和交易日历；
- 历史日线、调整因子、财务摘要和决算发表日历；
- 特征、信号和数据版本；
- 策略、参数、股票池和代码版本；
- 回测任务、运行日志和结果；
- 模拟账户、订单、成交、持仓及净值；
- 风险指标和绩效分析结果。

第一版不引入 Redis、Kafka、独立对象存储或分布式任务系统。后台任务由 PostgreSQL 任务表和单个工作进程串行执行；其他任务排队。取消任务时保留运行定义和进度，清理不完整明细，取消结果不得参与策略比较。

## 6. 数据规格

### 6.1 数据类别

| 类别 | 最低粒度 | 主要字段 | 用途 |
|---|---:|---|---|
| 上市标的主数据 | 快照 | 代码、名称、市场、行业、证券类别 | Prime 普通股股票池 |
| 日线行情 | 日 | OHLCV、成交额、调整价格、调整因子 | 研究、信号、回测 |
| 财务摘要 | 披露事件 | 披露时间、主要业绩与预测字段、版本 | 第二阶段基本面因子 |
| 决算发表日历 | 事件 | 计划发表日期、证券代码 | 事件提示与研究 |
| 模拟交易数据 | 模拟事件 | 订单、成交、持仓、现金、费用 | 组合和绩效分析 |

第一版数据源为 J-Quants API V2 Free。根据 2026-08-11 的官方资料调查，免费版约有滚动两年历史、延迟 12 周、限制 5 calls/min 且不支持 CSV 批量下载；免费端点包括上市标的主数据、股票全日日线、财务摘要和决算发表日历。TOPIX、官方交易日历、完整财务报表、现金股息明细及分钟/Tick 数据不属于 Free。

详细权限、来源和变化风险见 [J-Quants API 免费版可用数据调查](research/jquants-free-plan-data.md)。套餐可能变化，每次升级或重新实施数据适配器前必须复核官方资料。

第一版只使用全日日线。财务摘要完成接入和点时版本验证之前，策略仅使用价格、成交量与流动性因子。

### 6.2 点时一致性

研究数据至少保存：

- `event_time`：经济事件实际发生时间；
- `publish_time`：信息公开时间；
- `ingested_at`：系统导入时间；
- `effective_from/effective_to`：数据版本有效区间；
- `source` 和 `source_version`：来源及版本。

回测只能读取模拟时点已经公开且已生效的数据。财务数据不得按报告期末日期提前使用。同步程序必须记录每个端点实际返回的最早和最晚日期，不能硬编码“两年”的精确边界。

### 6.3 数据质量

导入时至少检查：

- 主键重复、字段缺失和时间倒序；
- 价格为负、成交量异常和 OHLC 逻辑错误；
- 停牌、零成交和交易日历一致性；
- 公司行动与复权因子的异常跳变；
- 财务数据发布日期、报告期和修订版本；
- 数据覆盖率、延迟和异常值。

严重错误的数据批次不得用于回测，并应保留错误原因。关键价格缺失时证券不可交易；非关键研究字段缺失时可以排除证券并告警；若缺失影响已持有证券估值或组合账务，整个任务失败，不得静默产生结果。

### 6.4 同步、修订与快照

- 后端按日或按周增量同步 J-Quants，并处理分页、每分钟 5 次限流、指数退避和 HTTP 429 重试；
- 回测只读 PostgreSQL，不在运行期间调用外部数据源；
- 规范化表保存当前值，同时记录来源版本、导入时间和发生变化的旧值；
- 已完成回测绑定不可变的数据快照，不随数据修订自动改变；
- 每次同步保存标的快照，为未来积累可靠的历史股票池；
- 免费历史无法证明包含完整退市证券，旧区间回测必须显示潜在幸存者偏差警告；
- 普通实验的详细事件默认保留 90 天，运行定义、汇总指标、月度净值和数据版本永久保留；重要运行可以固定全部明细。

## 7. 日本市场与股票池规则

### 7.1 市场范围

第一版仅包含东京证券交易所 Prime Market 普通股，排除 ETF、ETN、REIT、优先股及其他非普通股证券。基础币种为 JPY，只支持现金股票多头策略。

股票池在每个历史时点按当时保存的标的快照构建，并应用以下过滤：

- 最近约 20 个交易日平均成交额不少于 5 亿日元，阈值可配置；
- 有足够历史数据完成约 126 个交易日动量计算和约 21 个交易日跳过期；
- 决策日具有有效价格、成交量和证券状态；
- 免费数据无法确认完整退市历史时，显示幸存者偏差警告。

### 7.2 市场规则配置

日本市场规则通过配置管理：

- 交易日历和交易时段；
- 结算周期；
- 最小交易单位和价格精度；
- 涨跌停、停牌及不可交易状态；
- 手续费、税费和其他成本；
- 公司行动处理规则；
- 现金结算和可用资金规则。

所有规则仅用于历史模拟，不用于校验或发送真实订单。

J-Quants Free 不提供官方交易日历。第一版从历史日线实际出现日期推导历史交易日，但交易日历位于可替换的数据适配器接口；升级套餐或增加可靠来源后替换为正式日历。推导结果不得用于预测未来交易日。

## 8. 研究、信号与策略

### 8.1 因子研究

首个端到端基准策略为价格动量：

- 使用约 6 个月（126 个交易日）收益；
- 跳过最近约 1 个月（21 个交易日）；
- 每周按动量分数排序；
- 选择排名最高的 20 只股票；
- 采用等权目标，不使用排名缓冲或最低持有期；
- 周五收盘后决策；周五休市时使用该周最后一个交易日；
- 下一实际交易日开盘模拟成交；
- 窗口、持仓数和流动性阈值均可配置，但上述值是黄金测试基线。

第一阶段只支持价格、成交量、动量、反转、低波动和流动性类研究。价值、质量、成长等基本面因子在财务摘要点时语义验证完成后进入第二阶段。

研究结果应展示覆盖率、缺失率、分布、相关性、分组收益和样本外表现。

### 8.2 信号输出

信号至少包含：

- 证券和模拟日期；
- 策略及模型版本；
- 原始分数和标准化分数；
- 方向、置信度和原因码；
- 使用的数据快照；
- 失效条件或有效期。

### 8.3 策略版本

每次运行必须固定并记录：

- 策略定义和参数；
- 股票池及基准；
- 数据快照；
- 代码版本或构建标识；
- 费用、滑点和成交模型；
- 随机种子（如适用）。

策略作为已安装的 Python 模块注册，通过受控接口声明元数据、参数定义和信号计算。数据库仅保存参数和版本，禁止保存并执行任意 Python 代码。界面只提供少量已声明参数的配置能力。

参数试验按研究系列归组，必须展示试验次数、样本外结果和成本敏感性，降低挑选最佳结果造成的数据窥探偏差。

## 9. 组合与模拟风险

### 9.1 组合构建

支持：

- 等权、评分加权和优化权重；
- 单股、行业和市场权重上限；
- 最低现金比例；
- 换手限制；
- 最小持仓和最小调仓金额；
- JPY 现金和持仓估值。

首个策略的默认组合规则为：持有 20 只、等权、保留至少 5% 现金、单股目标权重不超过 5%。整手取整和费用导致无法精确达到目标时，剩余资金保留为现金。

### 9.2 模拟交易前检查

模拟订单生成前检查：

- 可用虚拟现金；
- 最大持仓和集中度；
- 股票是否处于可交易状态；
- 交易单位和价格精度；
- 成交量参与率；
- 预估费用、滑点和换汇需求；
- 调仓后组合约束。

风险检查失败时不生成模拟成交，并记录原因。

研究模式使用归一化净值；可执行性模式默认初始资金为 500 万日元，并同时提供 100 万、500 万和 1000 万日元的容量对比。可执行性模式模拟日本股票交易单位、现金余额及无法买入的目标仓位。

## 10. 回测与模拟成交

### 10.1 回测原则

- 使用点时一致的数据；
- 信号时间、下单时间和成交时间严格分离；
- 不允许使用当时尚未公开的数据；
- 不允许在没有成交量或不可交易状态下成交；
- 公司行动、退市和股票池历史变化必须被处理；
- 显式费用、滑点和现金结算假设必须写入结果。

### 10.2 成交模型

模拟成交支持配置：

- 默认使用下一交易日开盘价；
- 固定百分比滑点，默认单边 10 个基点且可配置；
- 成交量参与率上限；
- 手续费、税费和最低费用；
- 停牌、涨跌停及无成交量限制；
- 部分成交和未成交订单过期；
- 市场最小交易单位。

默认规则不得假设信号能够以生成信号时已经结束的同一根 K 线价格成交。

显式成本与滑点必须分开计算。系统提供：

- **零成本场景**：只用于观察信号理论表现；
- **基准成本场景**：用户配置佣金、最低费用和其他显式费用；
- **压力成本场景**：默认使用基准显式费用的两倍；
- **自定义场景**：允许覆盖显式费用和滑点参数。

预设不绑定或宣称代表任何券商的真实收费。结果同时展示毛收益、显式成本、滑点损失和净收益。

现金规则支持两种模式：默认模式允许卖出成交所得在同日调仓中使用；严格结算模式维护待结算现金，在结算完成前不可用于买入。

调整价格用于研究收益连续性。免费版没有完整公司行动及现金股息明细，因此不得从价格跳变臆测事件；可执行性回测只处理能够可靠识别的调整，并明确提示现金股息收益可能被低估。

### 10.3 模拟交易状态

模拟订单采用简化状态：

```text
CREATED → FILLED
        → PARTIALLY_FILLED
        → REJECTED
        → EXPIRED
```

状态由回测引擎和成交模型产生，不代表真实券商订单。

### 10.4 结果指标

至少计算：

- 累计收益和年化收益；
- 相对基准收益；
- 年化波动率；
- 最大回撤；
- Sharpe、Sortino 和 Calmar；
- 胜率和盈亏比；
- 换手率、交易次数和持有期；
- 显式费用、滑点及现金占用影响；
- 行业、市场和个股贡献。

内部基准为“当时可投资股票池的月度等权组合”，不是 TOPIX。结果同时展示基准毛收益和使用相同成本模型后的净收益，策略主要与净基准比较。

策略状态只允许：

- `EXPERIMENTAL`：逻辑、数据和黄金测试通过；
- `PROMISING`：样本外、成本和参数稳定性检查通过；
- `INSUFFICIENT_DATA`：观察期不足。

J-Quants Free 阶段禁止标记为 `VALIDATED`。约两年历史在扣除动量预热期后不能支持强统计结论，不能为了延长评估期临时缩短策略窗口。

## 12. 后端接口原则

接口采用版本化 REST。代表性接口：

```text
GET  /api/v1/instruments
GET  /api/v1/market-data/bars
GET  /api/v1/features
GET  /api/v1/signals
GET  /api/v1/strategies
POST /api/v1/backtests
GET  /api/v1/backtests/{id}
POST /api/v1/backtests/{id}/cancel
GET  /api/v1/backtests/{id}/results
POST /api/v1/replays
POST /api/v1/replays/{id}/decisions
POST /api/v1/replays/{id}/advance
POST /api/v1/replays/{id}/branch
GET  /api/v1/replays/{id}/comparison
GET  /api/v1/sim-accounts/{id}
POST /api/v1/sim-accounts/{id}/advance
GET  /api/v1/sim-accounts/{id}/orders
GET  /api/v1/sim-accounts/{id}/positions
GET  /api/v1/sim-accounts/{id}/performance
```

长时间任务使用任务 ID 查询状态，不要求前端保持长连接。写接口必须校验输入，并避免重复提交产生两次运行。历史重放查询由后端会话强制注入 `as_of`；前端传入更晚日期时必须拒绝请求，而不是只在界面隐藏数据。

## 13. 前端工作台

首期页面：

1. **仪表盘**：数据状态、近期回测、模拟组合和关键指标；
2. **数据中心**：数据覆盖、缺失、异常和导入任务；
3. **股票研究**：行情、财务、因子、事件和信号；
4. **策略中心**：策略参数、版本和股票池；
5. **回测中心**：创建任务、查看进度及比较结果；
6. **历史重放**：每周隐藏未来数据进行选股和目标权重决策；
7. **模拟账户**：虚拟现金、订单、成交、持仓和净值；
8. **绩效分析**：策略、用户和内部基准的收益、风险、回撤、成本及持仓差异；
9. **设置**：市场规则、费用模型、数据源和本地密钥说明。

所有结果必须明确标识为“历史回测”或“模拟交易”，不得表现为真实账户或真实成交。

## 14. 非功能要求

### 14.1 可复现性

- 相同输入产生相同输出；
- 每次运行保存数据、策略、参数和代码版本；
- 任务失败后可以从头安全重跑；
- 关键计算采用固定精度和明确舍入规则。

### 14.2 性能

- 常用页面查询 P95 小于 2 秒；
- 后台回测不得阻塞普通查询；
- 回测进度和预计处理范围可见；
- 第一版以 J-Quants Free 可见的约两年日线和 Prime 普通股为容量目标。

### 14.3 安全与备份

- Docker Compose 中前端和后端默认仅绑定 `localhost`，第一版不提供远程访问和登录；
- 密钥不得写入源码和日志；
- PostgreSQL 定期备份并进行恢复验证；
- 数据导入文件和回测导出文件限制在配置目录内；
- 依赖和镜像定期更新。

### 14.4 可维护性

- 前端、后端和数据库是仅有的部署单元；
- 后端模块接口清晰，避免业务逻辑散落在路由和 SQL 中；
- 数据库变更使用迁移脚本；
- 市场规则、费用和滑点通过配置或数据库管理；
- 日志包含任务 ID 和回测运行 ID，便于定位问题。

## 15. 推荐技术基线

- 前端：React / Next.js + TypeScript；
- 后端：Python + FastAPI；
- 数据处理：Polars 或 Pandas、NumPy；
- 优化：CVXPY（仅在需要组合优化时引入）；
- 数据库：PostgreSQL；
- 数据库访问：SQLAlchemy 或同类方案；
- 后台任务：单个后端工作进程 + PostgreSQL 任务表；
- 测试：Pytest、前端单元测试及端到端测试；
- 部署：个人电脑上的 Docker Compose，包含前端、后端和 PostgreSQL，仅监听本机。

第一版不使用微服务、Redis、Kafka、Kubernetes、独立对象存储和券商 SDK。

## 16. 测试与验收

### 16.1 测试层级

- 单元测试：因子、费用、复权、组合、现金和风险计算；
- 属性测试：账务恒等式、状态转换和数值边界；
- 集成测试：后端与 PostgreSQL、数据导入和任务运行；
- 黄金数据测试：固定数据快照对应固定信号及回测结果；
- 回放测试：完整历史区间的模拟交易；
- 时间隔离测试：历史重放的所有查询都无法读取 `as_of` 之后的数据；
- 数据适配测试：J-Quants 分页、限流、429 重试、修订和覆盖范围；
- 端到端测试：前端创建回测并查看结果。

### 16.2 验收条件

- 系统能够通过 J-Quants V2 Free 导入 Prime 普通股主数据和历史日线；
- 能运行 6 个月动量、跳过 1 个月、20 只等权的黄金基准策略；
- 能按周进行隐藏未来数据的历史重放，并创建不可覆盖的决策分支；
- 模拟订单、成交、持仓、现金和净值保持一致；
- 交易单位、不可交易状态、显式费用、固定滑点和现金模式按配置生效；
- 回测结果可追溯到策略版本和数据快照；
- 系统没有连接券商或发送真实订单的能力；
- 前端、后端和 PostgreSQL 可以通过单套部署配置启动。

## 18. 主要风险

| 风险 | 后果 | 缓解措施 |
|---|---|---|
| 数据偏差或未来函数 | 回测结果虚高 | 点时数据、历史成分、发布日期和黄金测试 |
| 过拟合 | 样本外失效 | 滚动验证、样本外测试、参数稳定性分析 |
| 流动性高估 | 模拟结果不现实 | 成交量参与率、滑点和容量压力测试 |
| 市场规则错误 | 成交与持仓失真 | 市场规则配置、固定案例和回放测试 |
| 免费版缺少完整公司行动和股息 | 收益被低估或账务不完整 | 使用调整价格、明确局限、只处理可靠事件 |
| 免费版历史过短 | 统计结论不可靠 | 禁止 VALIDATED 状态、显示观察点、满足条件后升级 Light |
| 幸存者偏差 | 策略收益虚高 | 显示警告、持续保存标的快照、升级后重新验证 |
| 本地数据损坏 | 历史结果丢失 | 定期备份和恢复演练 |
| 资源不足 | 回测过慢或失败 | 后台任务、查询索引、分批计算和容量限制 |

## 19. 已确认产品决策

1. 第一版市场为东京证券交易所 Prime Market 普通股；
2. 数据源为 J-Quants API V2 Free，只使用日线，免费阶段定位为原型；
3. 核心用途是量化策略验证、个人选股和目标权重建议；
4. 同时支持一次性回测和按周交互的历史重放；
5. 首个黄金策略为 6 个月动量、跳过 1 个月、20 只等权；
6. 内部基准为当时可投资股票池的月度等权组合，不冒充 TOPIX；
7. 默认初始资金 500 万日元，并比较 100 万和 1000 万日元；
8. 提供零成本、基准成本和压力成本，滑点默认单边 10 个基点；
9. Python 策略通过受控模块接口注册，界面只配置少量参数；
10. 单机 Docker Compose 部署，前端、后端和 PostgreSQL 仅监听本机；
11. 免费数据端到端验证完成且至少一个策略达到 `PROMISING` 后考虑升级 Light；
12. 系统不会连接券商，也不规划实盘交易。

## 附录 A：术语

- **点时一致性（Point-in-time）**：只使用历史时点当时已经公开的信息；
- **回测**：在一段历史区间内自动运行策略和模拟成交；
- **模拟交易**：基于历史数据产生虚拟订单、成交、持仓和净值；
- **数据快照**：一次运行所使用的数据范围和版本标识；
- **滑点**：模拟成交价相对参考价格的不利偏移；
- **最大回撤**：净值从历史高点到之后低点的最大跌幅。
